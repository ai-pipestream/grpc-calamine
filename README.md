# grpc-calamine

A gRPC server that reads Excel and OpenDocument workbooks with the Rust
[calamine](https://github.com/tafia/calamine) crate and **streams results
back to callers as they are parsed** — no buffering whole sheets into a
single response, no writing uploaded files to disk.

Supported formats: `.xls` / `.xla`, `.xlsx` / `.xlsm` / `.xlam`, `.xlsb`,
`.ods`.

## Design rules

- **No disk I/O for workbook content.** Uploaded bytes live in process
  memory (`Arc<[u8]>`) and are parsed with calamine's
  `open_workbook_*_from_rs` family. The server never saves a file.
- **Streaming reads.** XLSX and XLSB sheets are parsed incrementally via
  calamine's cell readers, so rows are emitted as the parser walks the
  sheet. XLS and ODS only offer whole-range parsing in calamine; those
  sheets are parsed and then streamed row by row. The wire contract is the
  same either way.
- **Highly concurrent.** A multi-threaded tokio runtime serves requests;
  all calamine work runs in the blocking pool. Each read request builds its
  own calamine reader over the shared in-memory bytes, so the read path is
  lock-free and many clients can stream the same workbook in parallel.
- **One-to-one contract.** The protobuf model in `proto/calamine/v1`
  mirrors calamine's public types exactly (`Data`, `Range`, `Cell`,
  `Sheet`, `ExcelDateTime`, `CellErrorType`, ...). No stringly-typed enums,
  no flattening, no lossy shortcuts. Conversions in `src/convert.rs` are
  total.

```

  types.proto            one-to-one data model (messages, enums)
  calamine_service.proto CalamineService: streaming RPCs

  proto.rs             includes the generated code (src/gen, do not edit)
  convert.rs           calamine <-> protobuf conversions
  store.rs             in-memory workbook store (Arc bytes, fresh readers)
  service.rs           the CalamineService implementation
  main.rs              multi-threaded server bootstrap
  gen/                 generated by `buf generate` — never edit by hand

  sample-data/           workbook fixtures (from the calamine test suite)
.github/workflows/     CI: build, test, fmt, clippy -Dwarnings, buf lint, typos
```

## Prerequisites

- Rust (stable), via [rustup](https://rustup.rs)
- [buf](https://buf.build/docs/installation) CLI
- Codegen plugins: `cargo install protoc-gen-prost protoc-gen-tonic`

The crate depends on stock calamine 0.36 from crates.io — no fork, no
patches. The contract's per-cell `is_1904` field is filled from the
workbook-level `has_1904_epoch()` readers (calamine PR #630): the epoch is
a property of the workbook, so the server reads it once at open time and
stamps it onto every streamed datetime.

## Run

```bash
cargo run
# grpc-calamine listening on 0.0.0.0:50051
```

Configuration via environment variables:

| Variable                         | Default        | Meaning                                  |
|----------------------------------|----------------|------------------------------------------|
| `GRPC_CALAMINE_ADDR`             | `0.0.0.0:50051`| Listen address                           |
| `GRPC_CALAMINE_WORKERS`          | CPU count      | tokio worker threads                     |
| `GRPC_CALAMINE_BLOCKING_THREADS` | `512`          | max threads for calamine parsing tasks   |

Hard limits (compile-time, `src/service.rs`): 512 MiB max workbook upload,
32 MiB max gRPC frame, 64-event stream backpressure channel.

## API overview

The service is handle-based: upload once, then issue any number of
concurrent reads against the returned `workbook_id`.

- `OpenWorkbook(stream OpenWorkbookRequest) -> OpenWorkbookResponse` —
  client-streaming upload. First frame carries `WorkbookOptions` (format
  hint, header row); remaining frames carry file bytes in order. Responds
  with `workbook_id`, the detected `WorkbookFormat`, and full `Metadata`.
- `CloseWorkbook` — releases the handle (idempotent-safe).
- `GetMetadata`, `GetDefinedNames` — workbook metadata snapshots.
- `StreamWorksheetRange` — server-streaming cell data: one `RangeStarted`
  header (sheet name, dimensions, total cells), then one `WorksheetRow`
  event per row, densely populated from the range start. Rows are emitted
  as parsed (XLSX/XLSB) or after range parsing (XLS/ODS).
- `StreamWorksheetFormula` — same shape, formula strings instead of values.
- `StreamVbaProject` — `VbaProjectInfo` header (references, module names),
  then one `VbaModule` event per module (raw MBCS bytes; decoding to UTF-8
  is a client concern, matching calamine's API).
- `GetPictures` — one `Picture` event per embedded image (requires
  calamine's `picture` feature, enabled in this build).

Error model: terminal failures use the gRPC status (`NOT_FOUND` for unknown
handles/sheets, `INVALID_ARGUMENT` for malformed uploads,
`RESOURCE_EXHAUSTED` for oversized workbooks). Recoverable per-item
failures on streams are delivered as in-band `StreamError` events carrying
a typed `CalamineError` (`CalamineErrorKind` + message), so one bad sheet
or module doesn't kill the rest of the stream.

## Client sketch (Rust)

```rust
// 1. Upload: first frame = options, then file bytes in <= 1 MiB chunks.
let frames = tokio_stream::iter(frames);
let opened = client.open_workbook(frames).await?.into_inner();

// 2. Stream a sheet by name or index.
let mut rows = client
    .stream_worksheet_range(StreamWorksheetRangeRequest {
        workbook_id: opened.workbook_id.clone(),
        sheet: Some(SheetSelector {
            selector: Some(sheet_selector::Selector::SheetName("Sheet1".into())),
        }),
    })
    .await?
    .into_inner();
while let Some(event) = rows.message().await? {
    // RangeStarted | WorksheetRow | StreamError
}

// 3. Release the handle.
client.close_workbook(CloseWorkbookRequest {
    workbook_id: opened.workbook_id,
}).await?;
```

## Testing notes

`cargo test` spins up a real tonic server on an ephemeral port and streams
real workbook files from `demos/sample-data` (originally from the calamine
test suite: `date.xlsx`, `date.xlsb`, `date.xls`, `date.ods`, `vba.xlsm`,
...). Every streamed cell is compared
against calamine's own `worksheet_range` output, and there are dedicated
tests for concurrent uploads, parallel streams of one workbook, in-band
errors, VBA modules, formulas, and datetime fidelity.
